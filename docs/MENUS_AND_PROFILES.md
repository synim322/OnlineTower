## Пользовательский поток

Обычный запуск открывает главное меню. «Играть» открывает создание, если персонажей нет, иначе выбор. Созданный персонаж сохраняется, затем «Войти в хаб» открывает игровой мир. Поддерживаются восемь локальных персонажей с именами «Странник NN». Доступно реализованное направление ДД ближнего боя; ульта «Раскол земли» остаётся прототипной.

Esc в игре открывает паузу: продолжить, **пригласить друга / группа** (поиск по нику, друзья, инвайт), настройки, главное меню, выход из игры. Группа для соло не обязательна — портал испытания ставит одиночку в очередь. В standalone мир не останавливается этим меню (только локальный ввод); в сетевой игре то же. Tab/E — меню испытаний. HUD: способности 1/2/3/R, откаты, здоровье; при входящих заявках/инвайтах — подсказка Esc → Друзья.

Общие настройки: громкость шагом 10%, четыре пресета графики, оконные разрешения 1280×720 / 1600×900 / 1920×1080 / 2560×1440, окно или окно без рамки размером рабочего стола. «Применить и сохранить» сохраняет настройки. Выбор разрешения переводит в оконный режим; эксклюзивный fullscreen не используется. Громкость предварительно применяется при изменении; для сохранения нужно нажать кнопку применения.

## Данные и границы

- `TowerFrontend.h/.cpp`: GameInstance, версионный SaveGame, главное меню и общие настройки.
- `TowerHub.h/.cpp`: игровой HUD, пауза и переключение ввода.
- `TowerCharacter.cpp`: блокирование боевых действий при открытом UI.
- `TowerAbilities.cpp`: восстановление сохранённых ID способностей в standalone authority.
- `Config/DefaultEngine.ini`: frontend по умолчанию, серверный HubGameMode, классы GameInstance и GameUserSettings.

Персонажи находятся в `Saved/SaveGames/TowerCharacters_v1.sav`. Формат хранит GUID, имя, направление и четыре стабильных идентификатора способностей; HP и откаты не сохраняются. Неизвестный/повреждённый формат не заменяется автоматически. Набор разыгрывается один раз при создании.

Локальные профили не являются сетевыми аккаунтами. Сетевой сервер продолжает существующую авторитетную выдачу прототипного набора и не доверяет клиентскому сохранению. Вход из главного меню открывает локальный хаб; существующий отдельный сетевой запуск сохранён.

## Проверки

- Полная сборка OnlineTowerEditor Win64 Development, UE 5.8.4: успешно.
- Automation: `OnlineTower.Abilities.WeightedUniqueLoadout`, `OnlineTower.Frontend.ProfileRoundtrip`, `OnlineTower.Frontend.ProfileValidation`: успешно, 3/3.
- Runtime `-TowerMenuProbe -TowerProfileSlot=TowerMenuProbe_20261030_A`: успешно. Создание/выбор → реальный travel и possession → соответствие способностей сохранению → pause/settings/resume → возврат в меню → проверка GUID/набора на диске. Проверка вызывает игровой API; физические клики мышью не автоматизированы.
- Визуально проверены `Saved/Screenshots/Menu-Main.png`, `Menu-Pause.png`, `Menu-HUD.png`, `Menu-PauseSettings.png`.
- Логи: `Saved/Logs/MenuProbe.log`, `MenuAutomation.log`, `Menu-*.log`.

Воспроизведение кадров: `Scripts/Capture-Menus.ps1 -View Main|Create|Settings|HUD|Pause|PauseSettings` (один вариант за запуск). Runtime probe требует новый слот с префиксом `TowerMenuProbe_`, существующий тестовый слот не перезаписывает. Скрипты сетевого запуска и окружения явно выбирают HubGameMode.

MCP редактора в этой сессии вернул `Transport closed`; использованы C++ и отдельные процессы Unreal. В `-game` логах присутствуют ошибки Python инициализации экспериментальных engine Toolsets; функциональный probe завершился успешно. Слуховая проверка громкости и ручной прогон всех кликов/изменения режима экрана не выполнялись.
