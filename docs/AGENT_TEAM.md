## Как работаем

Основной агент — координатор. Профили являются постоянными инструкциями специалистов, а не шестью постоянно работающими процессами. Их создание не запускает разработку игры автоматически.

Для сложной фичи: архитектор уточняет контракты; координатор назначает владельцев файлов; разработчики реализуют независимые части. Художник готовит визуальное ТЗ, 3D-художник делает модели, левел-артист собирает сцену. Параллельно выполняются только независимые работы. Координатор интегрирует результат и проводит необходимую общую проверку.

Количество одновременно работающих специалистов зависит от лимита сессии; остальные выполняются следующей группой. Не повышать лимиты или менять модель без необходимости.

Примеры запросов:

- «Пусть архитектор проверит архитектуру первого этажа и раздаст задачи двум разработчикам».
- «Подключи сетевого разработчика: проверим репликацию переката».
- «Художник и 3D-художник: сделайте портал по этому референсу, затем передайте левел-артисту».

Перед запуском роли координатор читает её профиль. Если текущий инструмент не поддерживает выбор custom agent по имени, координатор передаёт текст профиля в задаче обычному подагенту. Загрузка этих профилей клиентом автоматически ещё не проверена; запасной способ позволяет использовать их явно.

## Контекст проекта

Рабочий проект — `OnlineTower 5.8/OnlineTower.uproject`, модуль `OnlineTower`. В проекте включены GameplayAbilities, ModelContextProtocol и AllToolsets; доступность соединения проверяется отдельно.

Согласованные правила — `docs/PROJECT_DIRECTION.md`. Реализация хаба и известные ограничения — `docs/HUB_MULTIPLAYER.md` и `docs/HUB_PROTOTYPE.md`. Не считать исторические отчёты о тестах проверками текущего состояния.

Первая версия — один этаж. Финал: 12 игроков, четыре трио, без автоматического заполнения команд. Постоянный набор персонажа и состояние текущего матча должны быть разделены. Дальнейшие этажи, гильдии и аукцион не входят автоматически в задачи.

## Blender

Обнаружен исполняемый файл `C:/Program Files/Blender Foundation/Blender 4.3/blender.exe`. Установка или передача программы не требуется. В этой настройке проверено наличие файла, но производство модели и экспорт ещё не запускались.

Для работы можно запускать Blender локально с Python-скриптами; интерактивный MCP для Blender не является обязательным условием. При необходимости непосредственного управления открытой сценой подключение проверяется отдельно.

Исходники планируется хранить в `Art/Models/<asset>/`, концепты — `Art/Concepts/`, текстуры — `Art/Textures/`. Папки создаются по мере задач. Готовые ассеты импортируются в согласованный каталог Content после проверки масштаба, материалов и коллизий.

Если используется другой Blender, достаточно указать путь к его `blender.exe`. Для существующей модели нужен путь к `.blend` и связанным текстурам. Сначала проверяем доступ и создаём отдельный результат, сохраняя исходник.

Формат профилей сверён с официальной документацией: https://learn.chatgpt.com/docs/agent-configuration/subagents
