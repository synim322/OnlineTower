# Аккаунт, группа и поиск матча

Реализация от 2 ноября 2026. [English](MATCHMAKING_FLOW_EN.md). Рабочий проект: `OnlineTower 5.8/OnlineTower.uproject`, UE 5.8.4.

## Поток игрока

В обычном игровом окне: **Играть → выбор локального персонажа → Сетевая игра / аккаунт → регистрация или вход → хаб**. Backend и игровой сервер должны быть запущены. Сетевой набор умений пока выдаёт сервер; локальный профиль сохраняется отдельно и не становится серверным персонажем.

Esc открывает меню паузы (в том числе пункт **Пригласить друга / группа**) и блокирует только собственное управление. Мир, другие игроки и таймер поиска продолжают работать, в том числе в standalone. **Соло**: пати не нужна — один игрок входит в портал и ждёт набора в очереди. **Пригласить друга / группа**: найти игрока по нику (включая офлайн-аккаунты), добавить в друзья, затем «Пригласить в группу» или «Пригласить в группу по нику». Регистр букв не важен. Кросс-хабовое приглашение друга работает через backend: после согласия друг переезжает на хаб пригласившего и вступает в пати. Если оба уже на одном хабе, «Пригласить по нику» допускает и локальное приглашение без дружбы. Принять приглашение можно только из хаба/меню (не из очереди и не из матча). В PIE multiplayer окно уже в сессии listen-server: отдельный «войти в хаб» не нужен и не является ошибкой.

Группа содержит максимум **6 человек вместе с лидером**. Приглашать может лидер. Каждый участник группы должен войти в один и тот же портал для начала поиска; одиночка входит один. После постановки в очередь открывается меню поиска: испытание, таймер длительности поиска и число ожидающих / вместимость. Отмена — кнопкой в этом меню или в панели аккаунта. Когда набор полон, у всех появляется кнопка **Принять** с таймером **10 секунд**; кто не нажал — выходит из поиска, принявшие остаются в очереди. Группа больше вместимости испытания поиск не начинает.

| Портал | Полный состав | Урон между игроками |
|---|---:|---|
| Данж | 5 | Запрещён |
| Дуэль | 2 | Разрешён между двумя участниками того же матча, независимо от группы |
| Финал | 12 | Не добавлен; только поиск и вход |

Группа больше вместимости получает отказ без разделения. Подбор объединяет целые группы и одиночек, например 2+1+1+1. Он не добавляет людей в социальную группу. Отмена одним членом снимает заявку всей группы; повторный поиск требует выйти из портала и войти вновь. Выход из группы, изменение состава, потеря авторизации и отключение отменяют затронутую заявку.

## Проверка через Unreal Editor

Если появляется `Invalid backend response`, проверить запуск `Start-LocalBackend.cmd`: `http://127.0.0.1:18080/health` должен возвращать JSON `{"ok": true}`. При выключенном backend локальный HTTP-прокси может вернуть ответ не в JSON. В `DefaultEngine.ini` добавлено `[HTTP] HttpNoProxy=127.0.0.1,localhost`; перезапустить редактор для применения. Для multi-window PIE обязательно открыть `L_Hub`, а не `L_MainMenu`.

1. Запустить `OnlineTower 5.8/Start-LocalBackend.cmd`.
2. Открыть `/Game/Maps/Hub/L_Hub` в редакторе.
3. Play: **New Editor Window**, **Play As Listen Server**, **Number of Players = 5**, **Run Under One Process**. Для дуэли выбрать 2; для проверки ограничения группы — 7. Каждый игрок должен войти в отдельный аккаунт в своём окне. При первом входе окно автоматически показывает панель авторизации. PIE на одном listen-server использует `hub_a`; кросс-хаб проверяйте через `Start-Social-Hubs.cmd` / `Test-SocialMultiplayer.ps1`.
4. Для данжа можно пригласить одного друга по нику (или через друзей), а остальные окна оставить одиночками. Подвести участников к порталу данжа: до пятого матч не начинается. Проверить HUD ожидания, отмену и повторный вход. После набора пяти проверить отсутствие урона союзникам.
5. Для дуэли подвести два окна к её порталу. Проверить урон друг другу (даже если они в одной социальной группе). Смерть использует прежнее тренировочное возрождение; победитель и награда не реализуются этим изменением.

`Scripts/Configure-EditorMultiplayer.ps1 -Players 5` записывает настройки PIE при **закрытом редакторе**. Значение по умолчанию в проекте — 5. Скрипт сохраняет остальные пользовательские настройки.

**Два маршрута отличаются:** multi-window PIE начинается сразу на `L_Hub` с экраном входа; обычный клиент начинает с `L_MainMenu` и подключается к отдельному серверу. PIE на `L_MainMenu` не переносит весь listen-server мир после входа одного игрока. Для проверки именно меню использовать следующий запуск из корня репозитория:

```powershell
& './OnlineTower 5.8/Scripts/Start-HubMultiplayer.ps1' -Players 5
```

Он запускает локальный игровой сервер и пять игровых окон меню. Backend запускается отдельно. В каждом окне пройти вход; адрес по умолчанию `127.0.0.1:17777`, доступна настройка `-TowerServer=host:port` при запуске клиента. Скрипт печатает PID принадлежащего ему сервера и сохраняет список процессов. После ручной проверки закрыть свои окна и остановить этот сервер.

## Архитектура и границы

`Trials/TowerMatchmaking.*` — серверный WorldSubsystem с атомарными заявками групп. PlayerState реплицирует `MatchId`, а владельцу — `QueuedTrial`, `QueueStartedAt`, `QueuePopulation`. `TowerPartyComponent` проверяет приглашения по нику, лимит 6 и отмену. `TowerFrontend`, `TowerAccountSubsystem`, `TowerHub` показывают UI и отправляют запросы. `TowerCharacter` проверяет урон по испытанию и MatchId; клиент не определяет противников.

В локальном прототипе один серверный `L_Hub` содержит удалённые друг от друга площадки испытаний. Подобранный состав телепортируется на свою площадку; посторонние игроки остаются в хабе. На каждом типе площадки одновременно один активный состав. Следующая заявка ждёт её освобождения всеми участниками. Возврат через портал индивидуальный; он не переносит всю социальную группу. После смерти/возрождения участие очищается.

Это реальная локальная серверная очередь, но не интернет-матчмейкинг и не распределение по отдельным серверным процессам. Окружения реплицируются без дополнительных глобальных источников света. БД аккаунтов не хранит очередь или состав матча. Постоянный персонаж, сохранение результатов/наград, полноценные PvE-цели и правила победы остаются отдельной работой.

Финал получил только лимит/очередь/вход. Формирование трио, боевые правила, исход, награды и допуск по прогрессу не реализованы в этой задаче. Наличие числа 12 не подтверждает успешный прогон 12 окон.

## Автоматическая проверка

При свободных портах backend 18080 и игрового сервера 17779:

```powershell
& './OnlineTower 5.8/Scripts/Test-Matchmaking.ps1' -TrialIndex 0
& './OnlineTower 5.8/Scripts/Test-Matchmaking.ps1' -TrialIndex 1
& './OnlineTower 5.8/Scripts/Test-PartyLimits.ps1'
```

Запускать последовательно. Скрипты используют отдельную временную БД и скрытые реальные процессы Unreal с `-nullrhi`, завершают только свои процессы. Данж проверяет 5 участников и одного постороннего в хабе, дуэль — 2 и одного постороннего. Сценарий проверяет ожидание полного состава, репликацию таймера, MatchId, неизменность набора и политику урона. Это API/runtime проверка, а не автоматизация физических кликов мышью.

`Test-PartyLimits.ps1` использует семь клиентов и порт 17780 для лимита группы, отказов и отмены. Старый `Test-PartyMultiplayer.ps1` теперь направляет в актуальный тест данжа на 5.
