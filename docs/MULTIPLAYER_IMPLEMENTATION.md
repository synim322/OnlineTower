## Запуск вдвоём через Unreal Editor

Настройки двух окон PIE добавлены в `Config/DefaultEditorPerProjectUserSettings.ini` и применены к локальным настройкам редактора. Если старый пользовательский конфиг их переопределяет, при закрытом редакторе выполнить `Scripts/Configure-EditorMultiplayer.ps1`. Скрипт меняет только параметры Play, сохраняя остальные настройки.

1. Запустить `OnlineTower 5.8/Start-LocalBackend.cmd` и оставить окно открытым. Backend слушает `127.0.0.1:18080`; база создаётся в `Backend/data/tower.sqlite3` и сохраняется между запусками. Закрытие backend — Ctrl+C.
2. Открыть рабочий проект и карту `/Game/Maps/Hub/L_Hub`. Для Play выбрать **Number of Players = 2**, **Net Mode = Play As Listen Server**, **New Editor Window (PIE)**. Не запускать два независимых Standalone мира.
3. Запустить Play. В каждом окне открыть **Esc → ACCOUNT / PARTY**, зарегистрировать отдельный аккаунт через **Зарегистрироваться** либо войти через **Войти**. Имя: 3–24 латинские буквы, цифры или `_`; пароль: 8–128 символов. Одновременный вход одним аккаунтом в оба окна отклоняется игровым сервером.
4. Дождаться подтверждения аккаунтов. В первом окне выбрать **Пригласить** напротив второго игрока, во втором — **Принять приглашение**. Список приглашений обновляется автоматически. **Отклонить** отклоняет приглашение, **Выйти из группы** выводит игрока из пати.
5. Закрыть меню и подвести обоих персонажей к одному порталу. Первый ждёт внутри; переход начинается, когда все участники одновременно находятся в триггере. Вместимость испытания проверяет сервер.

PIE уже соединяет окна. Кнопка **Подключиться к локальному серверу** предназначена для отдельного запущенного сервера на `127.0.0.1:17777`, а не для переподключения PIE. В `DefaultEngine.ini` включён `net.AllowPIESeamlessTravel=1`, необходимый для seamless travel в редакторе.

| Действие | Кнопка |
|---|---|
| Камера во время игры | Движение мыши, без удержания ЛКМ/ПКМ |

Меню и режим курсора блокируют игровой ввод. В сетевой игре открытое меню не останавливает сервер и других игроков.

## Ответственность систем

- `Backend/server.py`: аккаунты и сессии в SQLite. Пароли хранятся как salted PBKDF2-HMAC-SHA256 (600 000 итераций), в БД сохраняются только хеши токенов; сессия действует 24 часа. Лимиты: 30 попыток регистрации/входа за минуту для локального сервиса, четыре параллельных вычисления хеша, тело запроса до 4096 байт. API и запуск описаны в `Backend/README.md`.
- `UTowerAccountSubsystem`: отдельное состояние входа для каждого GameInstance, включая отдельные PIE-клиенты. Токены находятся в памяти и не передаются через URL подключения.
- `UTowerPartyComponent`: запросы клиента к игровому серверу. Сервер проверяет токен через `/v1/auth/me`, допускает приглашения только подтверждённых игроков, проверяет принятие, вместимость пати (до трёх), срок приглашения и повторно валидирует сессию.
- `ATowerPlayerState`: реплицируемые идентификатор аккаунта, имя, идентификатор пати, лидер и набор умений. `CopyProperties` сохраняет нужное состояние при seamless travel.
- `ATowerPortal`: серверная проверка готовности всей пати и вместимости; смена карты через ServerTravel. GAS, урон и результаты остаются ответственностью игрового сервера.
- `TowerFrontend` и `TowerHub`: отображение состояния, поля входа и кнопки приглашений; UI не назначает членство в пати или результат испытаний.

## Ограничения текущей версии

Один локальный игровой сервер обслуживает одну текущую карту. Для смены отдельной карты все подключённые игроки должны принадлежать одной готовой пати. Посторонний игрок блокирует смену карты, чтобы ServerTravel не переносил его без согласия. Отдельные инстансы испытаний для разных пати пока не создаются.

Аккаунты сохраняются в backend, но персонажи и прогресс ещё не связаны с серверной БД. Сохранение набора при seamless travel не означает сохранение персонажа между сетевыми сессиями. Состав пати и приглашения не являются постоянными записями аккаунта.

Backend привязан к loopback HTTP. Публичное размещение, HTTPS, подтверждение почты, восстановление пароля и интернет-матчмейкинг не реализованы. Правила допуска и победы финального испытания этот прототип не заменяет.
