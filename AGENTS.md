# Команда OnlineTower

Рабочий проект: `OnlineTower 5.8/OnlineTower.uproject`. Не путать со старым путём `OnlineTower/`.
Требования: прежде всего актуальные инструкции пользователя, затем `docs/PROJECT_DIRECTION.md`; старые GDD/TechDoc — дополнительный контекст.
Перед задачами разработки читай `docs/AGENT_TEAM.md` и профиль подходящего специалиста в `.codex/agents/`.

## Делегирование

Для задач с несколькими независимыми направлениями используй специализированных подагентов команды. Для небольшой задачи достаточно одного исполнителя. Запускай только нужные роли, соблюдая фактический лимит сессии.
Основной агент координирует работу и интеграцию. Перед делегированием передай цель, контекст, файлы для чтения, разрешённые пути записи, зависимости и критерии приёмки.
Если интерфейс запуска не выбирает custom agent по имени, прочитай его TOML и передай developer_instructions в задании подагенту.
Не создавай отдельные пользовательские чаты без явной просьбы.
Архитектор определяет контракты для межсистемной задачи; исполнители работают параллельно только после разделения владельцев файлов.
Один автор на файл/бинарный ассет в момент времени. Управление живым Unreal Editor, сохранение карты, импорт, сборки и Live Coding выполняются последовательно.
Подагенты не делегируют дальше без назначения основного агента.

## Общие требования

- Сохраняй существующие пользовательские изменения; не очищай рабочее дерево ради задачи.
- Различай подтверждённые правила, прототип и предложения.
- Сервер определяет урон, способности, команды, результаты и награды.
- Используй профильные skills для Unreal, генерации изображений и производства/импорта ассетов.
- Наличие MCP-плагина не означает наличие живого соединения. Проверяй инструменты перед работой.
- Не меняй .uasset/.umap текстовыми операциями.
- Проверяй соразмерно изменению. Отчёт включает результат, пути, реально выполненные проверки и ограничения.
- Не утверждай готовность к 12 игрокам по тесту с двумя клиентами.
